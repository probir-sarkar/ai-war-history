# War History Archive

A browsable archive of historical wars and battles: wars indexed with battle
counts, battles cross-referenced to their parent war, participants, outcomes,
and coordinates. Server-rendered with per-page SEO metadata.

## Stack

- **[TanStack Start](https://tanstack.com/start)** (React 19, SSR, file-based routing)
- **[oRPC](https://orpc.uniconr.com/)** — type-safe API layer (RPC + OpenAPI handlers)
- **[Drizzle ORM](https://orm.drizzle.team/)** + PostgreSQL (via Cloudflare Hyperdrive)
- **[Tailwind CSS v4](https://tailwindcss.com/)**
- Deployed to **Cloudflare Workers**

## Getting started

Prerequisites: [Bun](https://bun.sh), a PostgreSQL database, and (for deploy)
a Cloudflare account.

```bash
bun install
cp .env.example .env   # fill in DATABASE_URL
```

For local dev, wrangler provisions a local Hyperdrive-backed database from
`CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE` in `.env`.

```bash
bun run dev            # start dev server on :3000
```

## Database

Schema lives in `src/db/schema.ts`, migrations in `migrations/`.

```bash
bun run db:generate    # generate a migration from schema changes
bun run db:migrate     # apply migrations
bun run db:push        # push schema directly (dev only)
bun run db:studio      # browse data
bun run db:seed        # seed from data-clean/cleaned_data.json
```

## API

The oRPC router (`src/orpc/router/`) is exposed two ways:

- **RPC** at `/api/rpc` — used by the app client (`src/orpc/client.ts`)
- **OpenAPI** at `/api` — REST-style endpoints with schema coercion

## Deploy

```bash
bun run deploy
```

Secrets: `wrangler secret put MY_VAR` for each server secret. The Hyperdrive
binding is configured in `wrangler.jsonc`.

## Conventions

- Route data flows through oRPC procedures; list pages paginate via URL search
  params (`?page=`, `?q=`) so state is shareable and SSR-friendly.
- Shared formatters live in `src/lib/` (`formatYear`, `formatLatitude`, …).
- Route types are generated by the TanStack Router Vite plugin
  (`src/routeTree.gen.ts`, not committed) — run `bun run build` or `bun run dev`
  to regenerate after route changes.
